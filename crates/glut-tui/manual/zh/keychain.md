让钥匙串远离 Glut 运行的命令。

/keychain — 它是否开放，以及可以请求它的程序
/keychain add <program> — 把一个程序加入列表（gh，或 git 加子命令：git push）
/keychain remove <program> — 把它从列表中移除
/keychain open — 对所有命令开放，直到本会话结束
/keychain close — 再次关闭它

钥匙串中的密钥或登录可以绕过沙盒的每条文件规则被读取，所以 Glut 运行的命令看到的钥匙串是关闭的。列表中程序的命令会先询问 — 在每种模式下，包括 `auto` — 你允许后便在钥匙串开放的情况下运行；“总是”会把它变成你的一条规则。没有人在场时（计划、`glut run`），只有这样的规则才能打开它。当命令因钥匙串关闭而失败时，Glut 会在其输出下方说明。

允许一个命令，也就把钥匙串交给了它启动的一切：git Hook、gh 扩展或构建脚本都可以读取其中的任何密钥。

只有你自己的规则能放行钥匙串：项目 `.glut/` 中的允许规则可以让命令运行，但绝不会打开钥匙串。命令链只有在每个部分都在列表中或只读取时才能获得它。`glut keychain open` 保持的打开状态只在这里（你在场时）有效 — 在 `glut run` 或宿主的运行中从不生效。

你的规则只有在指明程序及其子命令时（`gh pr *`、`git push *`）才会不经询问打开它 — 从不针对整个程序（`gh *`）。🔑 卡片显示完整命令，用 ↑↓ 浏览，读到末尾后才能允许。

列表保存在 `~/.glut/keychain.json`；`glut keychain open` 让钥匙串跨会话保持开放，`glut keychain close` 永久关闭它。
