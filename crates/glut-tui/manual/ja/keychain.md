Glut が実行するコマンドからキーチェーンを遠ざけます。

/keychain — 開いているかどうかと、それを求めてよいプログラム
/keychain add <program> — プログラムをリストに加えます (gh、または git とサブコマンド: git push)
/keychain remove <program> — リストから外します
/keychain open — このセッションが終わるまで、すべてのコマンドに開きます
/keychain close — 再び閉じます

キーチェーンの鍵やサインインはサンドボックスのどのファイル規則もすり抜けて届くため、Glut が実行するコマンドにはキーチェーンが閉じています。リストのプログラムのコマンドはまず尋ね — どのモードでも、`auto` でも — あなたが許可するとキーチェーンを開いて実行します。「常に」はあなたのルールになります。誰もいないとき (プラン、`glut run`) は、そのようなルールだけがそれを開きます。閉じたキーチェーンでコマンドが失敗すると、Glut はその出力の下でそう伝えます。

コマンドを許可すると、それが起動するものすべてにもキーチェーンが渡ります: git Hook、gh の拡張、ビルドスクリプトがその中のどの鍵でも読めるようになります。

キーチェーンを渡せるのはあなた自身のルールだけです：プロジェクトの `.glut/` の許可ルールはコマンドを実行させますが、キーチェーンを開いた状態にはしません。コマンドの連結は、すべての部分がリストにあるか読み取りだけの場合にのみ受け取ります。`glut keychain open` が開いたままにする設定は、あなたがいるここでのみ有効で — `glut run` やホストの実行では決して有効になりません。

あなたのルールが確認なしで開くのは、プログラムとそのサブコマンドを指定している場合だけです（`gh pr *`、`git push *`）— プログラム全体（`gh *`）は決してありません。🔑 カードはコマンド全体を表示し、↑↓ でたどり、最後まで読んで初めて許可できます。

リストは `~/.glut/keychain.json` に保たれます。`glut keychain open` はセッションをまたいでキーチェーンを開いたままにし、`glut keychain close` は永久に閉じます。
